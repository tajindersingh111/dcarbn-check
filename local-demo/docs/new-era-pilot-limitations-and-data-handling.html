Limitations & data handling

Mandatory pilot notice

A local demonstration—not a hosted production service.

Read this notice before preparing files or starting the New Era customer pilot.

Do not upload identifiable, confidential or commercially sensitive data. The pilot is approved only for fictional or irreversibly anonymised data. If there is any doubt, do not use the file.

Approved for this pilot

  • Committed fictional demonstration files.
  • Irreversibly anonymised 2025 activity data that cannot be linked back to a person, supplier, customer, contract, site or commercially sensitive transaction.
  • Supervised use on Leonard’s designated demonstration laptop.

Not approved

  • Names, email addresses, telephone numbers or employee identifiers.
  • Customer, supplier, vehicle, meter, account, contract or invoice identifiers that reveal a real party.
  • Prices, volumes, routes, locations or operational detail that is confidential or commercially sensitive.
  • Independent remote customer access to the local pilot.

Where the data is held

The pilot has no application database and does not upload customer files to D-carbN servers. Imported CSV content, validation results, calculations, workflow state and audit history are stored only in the browser on Leonard’s demonstration laptop. Closing the tab does not necessarily clear that browser storage.

Controls and their limits

  • The pilot uses a local security gate, inactivity locking and encrypted session exports. The passphrase is not stored and cannot be recovered.
  • Browser storage is not a substitute for production access control, managed backups, central audit monitoring, retention controls or tenant isolation on a hosted service.
  • Operating-system accounts, device security, browser extensions, screen sharing, screenshots, download folders and backup software sit outside the pilot application’s control.
  • Evidence references record lineage, but external evidence documents are not automatically embedded in the encrypted session export.
  • The pilot report demonstrates the workflow and format. It is not an independently assured statement and must not be used as a production disclosure.

Required handling procedure

  1. Leonard checks every proposed file against this notice before it is opened or uploaded.
  2. Use only the local address http://127.0.0.1:8081/ on the designated laptop.
  3. Keep passphrases separate from encrypted exports and never place a passphrase in a CSV, screenshot, form, chat or email.
  4. During the session, display only the pilot and the approved fictional or anonymised files.
  5. At the end, export only the agreed non-sensitive outputs, select Clear all local customer data, delete unnecessary downloads and temporary files, and stop the local server.
  6. Report any accidental exposure immediately without copying the exposed information into the feedback record.

Remote access and the next phase

This browser pilot is designed for a supervised demonstration on one local computer. Independent access from New Era computers—including direct access across the internet—requires the protected hosted platform with authenticated users, role-based permissions, tenant isolation, managed encrypted storage, monitoring and governed operational controls. Do not expose the local server publicly or use consumer file-sharing as a substitute.

Decision rule: if the customer needs to use real business data or access the application independently, pause the browser pilot and move that activity into the approved hosted-platform plan.

Pre-session acknowledgement

  • The approved data boundary has been explained.
  • All files have been confirmed fictional or irreversibly anonymised.
  • The local-storage limitation and end-of-session clearing process are understood.
  • Independent remote access has not been offered or enabled.
